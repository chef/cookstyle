# Cookstyle Developer Guide

Orientation for working on Cookstyle itself. If you're here to add or change a cop, read [WRITING_RULES.md](WRITING_RULES.md) — this document covers everything around that.

For the Chef community's general contribution policy, see [Contributing to Progress Chef Workstation](https://chef.github.io/chef-oss-practices/projects/workstation/contributing/).

## Getting set up

```bash
git clone https://github.com/chef/cookstyle.git
cd cookstyle
bundle install
bundle exec rake
```

`rake` with no arguments runs the default task: lint, specs, and config validation. The whole thing takes a few seconds.

CI tests against Ruby 3.1, 3.4, and 4.0 on Ubuntu and Windows. Any of those is a fine local development version.

To run the binary from a checkout:

```bash
bin/cookstyle path/to/cookbook
```

## What Cookstyle actually is

Cookstyle is RuboCop plus three things:

1. **A vendored configuration** (`config/cookstyle.yml`) that turns off most upstream RuboCop cops, tunes some of the rest, and enables the Chef-specific ones. `DisabledByDefault: true` means a cop is off unless the config names it.
2. **Chef and InSpec cops** under `lib/rubocop/cop/`.
3. **A handful of monkey patches** under `lib/rubocop/monkey_patches/` that add the `TargetChefVersion` config option, accept `# cookstyle:disable` alongside `# rubocop:disable`, and adjust a warning message.

`bin/cookstyle` is a shim that requires the `cookstyle` library — which swaps RuboCop's default configuration for the vendored one — and then hands off to RuboCop's own binary. It also appends `--fail-level C` and `--display-style-guide`, which is what implements the stability promise described in the README: new cops ship at `refactor` severity and print without failing anyone's build.

Because the monkey patches reach into RuboCop internals, the gemspec pins RuboCop to an exact version (`Cookstyle::RUBOCOP_VERSION` in `lib/cookstyle/version.rb`). Bumping RuboCop means bumping that constant and re-checking the patches.

## Repository layout

```
bin/                  cookstyle and cookstyle-profile executables
config/
  cookstyle.yml       the vendored config — every cop needs an entry here
  chefstyle.yml       config for `cookstyle --chefstyle`, Chef's own Ruby style
  default.yml         thin file that inherits from cookstyle.yml
lib/
  cookstyle.rb        entry point; loads cops and swaps RuboCop's default config
  cookstyle/          version constants
  rubocop/
    chef/             shared mixins for cops (cookbook, platform, autocorrect helpers)
    cop/chef/         the Chef Infra cops, one directory per department
    cop/inspec/       InSpec profile cops
    cop/chefstyle/    cops for Chef's own Ruby code, used by --chefstyle
    monkey_patches/   patches against RuboCop internals
spec/                 mirrors lib/, one spec file per cop
tasks/                rake tasks for docs, profiling, and spellcheck
docs-chef-io/assets/  generated per-cop YAML consumed by docs.chef.io
habitat/              Habitat packaging
.expeditor/           release automation
```

`docs/` holds stub files left over from a documentation system retired in 2021. Cop documentation lives at [docs.chef.io](https://docs.chef.io/workstation/cookstyle/) and is generated into `docs-chef-io/assets/`.

### Files not to edit by hand

- `docs-chef-io/assets/cookstyle/*.yml` — generated by `rake generate_cops_yml_documentation`
- The cop count in `README.md` — generated by `rake update_readme_cop_count`
- `CHANGELOG.md`, `RELEASE_NOTES.md`, `VERSION` — maintained by Expeditor
- `docs-chef-io/go.mod` — managed by the docs site tooling

## Rake tasks

| Task | What it does |
| --- | --- |
| `rake` | Default: `style`, `spec`, and `validate_config` |
| `rake spec` | The RSpec suite |
| `rake style` | Runs Cookstyle against itself |
| `rake validate_config` | Fails if a cop in `lib/` has no entry in `cookstyle.yml` or `chefstyle.yml` |
| `rake generate_cops_yml_documentation` | Regenerates the docs.chef.io assets from YARD comments |
| `rake update_readme_cop_count` | Updates the cop count in the README |
| `rake documentation_syntax_check` | Parses every `@example` block to confirm it's valid Ruby |
| `rake docs` | YARD documentation |
| `rake prof:slow_cops` | Profiles a run and lists the slowest cops |
| `rake console` | IRB with Cookstyle loaded |

This project does not measure test coverage — SimpleCov is not a dependency and no coverage report is produced.

## Testing

Specs live under `spec/`, mirroring `lib/`, and use RuboCop's `expect_offense` helpers. See [WRITING_RULES.md](WRITING_RULES.md#writing-the-spec) for the conventions, including the requirement that every cop has a negative case.

```bash
bundle exec rake spec                                   # everything
bundle exec rspec spec/rubocop/cop/chef/style/          # one department
bundle exec rspec spec/path/to/a_spec.rb:42             # one example
```

## Performance work

Cookstyle runs across large cookbook repositories in CI, so cop performance matters. `tasks/prof.rake` wires up stackprof:

```bash
bundle exec rake prof:run       # profile a run against the current directory
bundle exec rake prof:slow_cops # list the slowest cops
```

The two highest-leverage things in a cop are setting `RESTRICT_ON_SEND` and setting `Include`/`Exclude` in the config. Both stop the cop being invoked at all for irrelevant code.

## Chefstyle

`cookstyle --chefstyle` loads `config/chefstyle.yml` and the cops under `lib/rubocop/cop/chefstyle/` instead of the cookbook set. This is the style used on Chef's own Ruby projects, not on cookbooks. It shares the `RuboCop::Cop::Chef` namespace but ships a separate config, which is why `rake validate_config` checks each cop against the config matching where it's defined.

## Pull requests

**Sign your commits.** Every commit needs a DCO signoff or the build fails:

```bash
git commit --signoff -m "Your message"
git commit --amend --signoff --no-edit   # to fix a commit that's missing one
```

**Label the PR.** The labels drive both the changelog and the release automation:

| Change | Labels |
| --- | --- |
| New cop or feature | `Type: Enhancement` |
| Bug fix | `Type: Bug` |
| Documentation only | `Aspect: Documentation`, `Expeditor: Skip All` |
| Tests only | `Aspect: Testing`, `Expeditor: Skip Version Bump` |
| Security fix | `Aspect: Security`, `Priority: Critical` |

Expeditor skip labels: `Expeditor: Skip All`, `Expeditor: Skip Version Bump`, `Expeditor: Skip Changelog`, `Expeditor: Skip Habitat`, `Expeditor: Skip Omnibus`.

Review comes from the teams in [CODEOWNERS](.github/CODEOWNERS).

## Releases

Releases are automated by [Expeditor](https://expeditor.chef.io/), configured in `.expeditor/config.yml`. On merge to `main` it bumps the patch version in `VERSION` and `lib/cookstyle/version.rb`, updates `CHANGELOG.md`, regenerates the cop documentation, and publishes the gem to RubyGems.

Add `Expeditor: Bump Version Minor` or `Expeditor: Bump Version Major` to the PR for a larger bump, or a skip label for changes that shouldn't ship a release.

New cops go out at `refactor` severity so they never break an existing build. Promoting a cop to a higher severity, removing a cop, or changing a default is a major-release change — historically aligned with Chef Infra's April release.

## Bumping RuboCop

1. Update `RUBOCOP_VERSION` in `lib/cookstyle/version.rb`
2. `bundle update rubocop`
3. Run `bundle exec rake` and read the diff in behavior carefully

Pay particular attention to `lib/rubocop/monkey_patches/`. `team.rb` in particular contains a copy of an upstream private method with one condition added; if RuboCop changes that method, the patch will keep running the old logic without any error. Compare it against the installed RuboCop source when bumping.

New upstream cops do not turn themselves on — `NewCops: disable` is set — so a RuboCop bump never changes what users see unless `config/cookstyle.yml` is edited to enable something.
